# 忘却曲線 英単語（英検7級〜1級）

index.html をブラウザで開くと使えます（インターネット接続は不要）。

## ファイルの構成
- index.html / css/style.css / js/app.js … アプリ本体
- js/config.js / js/sync.js … Googleアカウントでの同期（クライアントIDを config.js に入れると使えます）
- privacy.html / terms.html … プライバシーポリシー・ご利用案内／利用規約（公開前に、運営者名・連絡先・制定日の【　】を書き換えてください）
- js/data/words_○.js … 級ごとの単語データ（7,6,5,4,3,p2=準2,2,p1=準1,1）
- data/words_master.json … 単語データの元（全級・テーマ・ふりがな入り）
- data/txt/○級英単語.txt … 元のtxtと同じ形式（#, 英語, 日本語, 品詞）で書き出したもの
- data/theme_overrides.tsv … テーマの手動修正
- build_web.py … words_master.json から js/data と data/txt を作り直すスクリプト
- data/books/○○.json … 本のデータ（本文と、学習する単語・フレーズ）
- build_books.py … data/books の内容から js/data/book_○○.js を作り直すスクリプト
- make_kana.py … カタカナ表記を作るスクリプト（data/kana_overrides.tsv で手動修正）

## 単語の追加・修正
1. data/words_master.json を編集（追加方法は build_web.py の冒頭に書いてあります）
2. python3 build_web.py を実行
3. ブラウザで Ctrl+F5

## データについて
- 元の9ファイル 15,247語 → 重複を1つにまとめて 9,893語 → 不足していた基本語 502語を追加 → 10,395語
- 同じ単語が複数の級にあった場合は、いちばん易しい級に入れています。意味は1つにまとめています。
- 6級・7級：元の2つのリストはほぼ同じ範囲でした。重なりをまとめた小学生レベルの語を、よく使う順に半分ずつ（7級＝より基本的な語、6級＝その次）に分けています。
- 品詞が空だった3,433語は、辞書データから推定した値です。
- テーマは、辞書データと日本語の意味から自動で分けたものです。ずれている語は theme_overrides.tsv で直せます。
- ふりがなは、3〜6級は元データの読みを使い、そのほかは辞書ソフトで自動生成しました（読み違いが残っている可能性があります）。

## 本（7つの物語）
- 画面左上の「📖 本」スイッチで、本のページと「忘却曲線 英単語」のページを切り替えます。本のページでは、上の「本」から物語を選びます。
- 収録：The Three Little Pigs／Three Little Kittens／The Three Bears／Chicken Little／The Gingerbread Man／The Old Woman and Her Pig／The Owl and the Pussy-Cat
- 本文は、どれも昔話や古い作品をもとに、学習用にやさしい英語で書いた再話です（原文そのものではありません）。
- 本ごとに「学習」「復習」「忘却テスト」「定着度グラフ」があります。
- 同じ英単語が、別の本や「忘却曲線 英単語」にもある場合は、学習記録（定着度）が共有されます。
- 意味が1語ずつでは分からない表現（once upon a time／run away／at last など）は、フレーズとして学習します。
- 動詞には「（過去形：ran（走った））」の形で過去形を表示します。
- 設定の「最初に開くページ」で、起動時に開くページを選べます。
- 本を足すには、data/books/ に同じ形式のJSONを置いて python3 build_books.py を実行し、index.html に js/data/book_○○.js の読み込みを1行足します。

## 学習記録の保存について
- 学習記録は、ブラウザの中（localStorage）に保存されます。GitHubへのアップロードや再読み込みでは消えません。
- 1語を間違えずに3回打ち終えるたびに、その場で保存されます（途中でブラウザを閉じても、打ち終えた語は残ります）。
- 「設定・データ」に、保存されている語数と最後の保存時刻が表示されます。開き直したときの確認にお使いください。
- Chromeの「ウィンドウをすべて閉じたときに、Cookieとサイトデータを削除する」設定がオンだと、閉じるたびに記録が消えます。
- 読み込めない保存データがあっても、空のデータで上書きしません（元のデータを退避して知らせます）。
- 3時間に1回、自動バックアップを残します。保存データが見つからないときは、そこから復元します。
- IndexedDBにも控えを残します。localStorageだけが消えたときは、そこから復元します。
- ブラウザのデータ自体が消える場合（サイトデータの自動削除、PCの復元ソフト、別のChromeプロフィールなど）は、アプリでは防げません。
  「設定・データ」の「データをエクスポート」で、ときどきバックアップファイルを保存してください（1週間以上書き出していないと、上部に案内が出ます）。

## Googleアカウントで学習記録を同期する（Google Drive）
ログインしたGoogleアカウントの Google Drive（アプリ専用の非表示フォルダ）に、学習記録を自動で保存します。
別の端末で同じアカウントでログインすると、自動で取り込みます。保存先は利用者それぞれのGoogle Driveで、開発者のサーバーは使いません。
使う権限は「このアプリ専用のフォルダ（drive.appdata）」と「メールアドレスの表示」だけです。Driveのほかのファイルは見えません。

### 最初に1回だけ必要な設定（開発者がやります。約10分）
1. https://console.cloud.google.com/ を開き、プロジェクトを作ります（名前は何でもよいです）。
2. 「APIとサービス」→「ライブラリ」で **Google Drive API** を検索して「有効にする」。
3. 「APIとサービス」→「OAuth 同意画面」（または「Google Auth Platform」）で、次のように設定します。
   - ユーザーの種類：外部／アプリ名・サポートメール：入力
   - スコープ：`.../auth/drive.appdata` と `.../auth/userinfo.email` を追加
   - 公開ステータスを **「本番環境」** にする（「テスト」のままだと、登録したテストユーザーしかログインできません）
4. 「認証情報」→「認証情報を作成」→「OAuth クライアント ID」→ 種類は「ウェブ アプリケーション」。
   - 「承認済みの JavaScript 生成元」に、公開するURLのドメイン（例：`https://ユーザー名.github.io`）を入れます。パス（`/リポジトリ名`）は付けません。
   - 試すだけなら `http://localhost:8000` も追加できます。
5. 表示された **クライアントID**（`〇〇.apps.googleusercontent.com`）を、`js/config.js` の `GOOGLE_CLIENT_ID = ''` の中に貼り付けて、GitHubへアップロードします。
※ ファイルを直接開く（file://）と、Googleのログインは使えません。https のURLで開いてください。

### 使い方（利用者）
- 画面上部の「☁」または、設定の「Googleでログイン」を押して、Googleアカウントでログインします。
- 学習すると、15秒ほどまとめてから自動でアップロードします。ほかの端末で更新した分は、5分ごと・画面に戻ったとき・ログイン直後に取り込みます。
- ログインの有効期限は約1時間です。切れたときは、画面を最初にタップすると自動で再開します。再開しないときは「☁?」を押してください。
- 同じ単語を2つの端末で学習した場合は、新しいほうの記録を採用します。別々の単語を学習した場合は、両方の記録がそろいます。
- 「データをリセット」「インポート」をした端末の内容が優先され、ほかの端末にも反映されます（反映される前の記録は、その端末のブラウザの中に退避されます）。
- 「同期をやめる」を押しても、この端末の記録とDriveの記録は残ります。

### Google Drive のデータを削除する
- 設定・データ →「Google Drive のデータを削除」：Driveに保存された同期データだけを消します（この端末の記録は残り、同期は止まります）。
- 設定・データ →「データをリセット」：この端末の記録を空にします。同期中なら、ほかの端末の記録も空になります。
- 利用者のGoogleアカウント →「セキュリティ」→「サードパーティのアプリとサービス」から、アクセスを取り消すこともできます。

### 不特定多数へ公開するときのチェックリスト
1. privacy.html の【運営者名】【連絡先メールアドレス】【制定日】を書き換えて、GitHub Pagesに置く。
2. Google Cloud コンソール →「ブランディング」：アプリ名、ユーザーサポートメール、デベロッパーの連絡先メール、アプリのホームページ（index.html のURL）、プライバシーポリシー（privacy.html のURL）を入力。ロゴは、設定すると確認が必要になることがあるため、最初は入れない。
   - 承認済みドメインに `github.io` を追加できない場合は、独自ドメインを取得して、GitHub Pagesに割り当ててください。
3.「データアクセス」：スコープ `drive.appdata` と `userinfo.email` を追加し、分類が「非機密」になっているか確認する。「機密」「制限付き」と表示された場合は、Googleの確認（審査）が必要です。
4.「クライアント」：「承認済みの JavaScript 生成元」に、本番のドメインを入れる。
5.「対象」：公開ステータスを「本番環境」にする（「アプリを公開」）。
6. 公開後、テストユーザーに登録していない別のGoogleアカウントでログインして、動作を確認する。

### Google Cloud「ブランディング」に入れるURL
- アプリケーションのホームページ：アプリのトップページ（例：`https://ユーザー名.github.io/リポジトリ名/`）
- アプリケーション プライバシー ポリシー リンク：`https://ユーザー名.github.io/リポジトリ名/privacy.html`
- アプリケーション利用規約リンク：`https://ユーザー名.github.io/リポジトリ名/terms.html`（任意）
